# 毎日使える Creative AI Studio へ向けた UI/UX 改善提案

## 結論

最優先は、生成機能を増やすことではなく、利用者が毎回同じ迷いなく
「開く → 目的を伝える → 結果を比較して直す」まで完了できる体験にすることです。

既存の `Job`、`Asset`、`Project`、モデル可用性、再利用、フィードバックの基盤を
そのまま活かし、日常利用用の画面を **かんたん作成** として再構成します。現在の
詳細な Composer は **詳細調整** として残すため、制作に慣れた利用者の自由度も失いません。

## 現状から読み取れる課題

| 利用者の声 | 現状の要因 | 体験上の問題 |
| --- | --- | --- |
| 起動が面倒 | API と Web UI を別々に起動し、モデル配置も別途必要 | 作品づくりの前に環境運用が始まる |
| 操作方法が分かりにくい | 最初から media / project / model / prompt / advanced parameter が同じ密度で見える | 何を先に決めるべきか分からず、判断疲れが起こる |
| 使えるハード・環境が限られる | ローカルモデル前提で、端末性能・モデル準備・ブラウザ到達性が利用の前提 | 開いても生成できない理由や代替手段が分かりにくい |
| 思い通りに生成されない | 意図を構造化して渡す補助、結果からの修正、比較の導線が弱い | 「再生成」を繰り返すだけになり、改善理由を学習できない |

## 目指す日常の体験

利用者が毎日行う代表的な仕事を、3 分以内に始められる状態にします。

```text
開く
  ↓ 端末とモデルの準備状況が一目で分かる
今日つくるものを選ぶ（画像 / 動画 / 音楽）
  ↓ 目的別の短い質問に答える
生成する
  ↓ 待ち時間・残り作業・中止が明確
結果を「使える / 直したい」で判定
  ↓ 修正したい点を選ぶだけで次の案を作る
比較・採用・書き出し
```

この流れでは、プロジェクト、モデル、LoRA、seed、詳細パラメータは必要なときだけ現れます。

## 提案する改善

### 1. 起動を「アプリを開く」操作にする

**体験**

- macOS 向けには Dock から開ける Launcher、Windows/Linux 向けには同じ役割のデスクトップ用起動スクリプトを用意する。
- Launcher は API、Web UI、ブラウザ起動をまとめて行い、すでに起動中なら Studio を前面表示する。
- 初回だけ必要なセットアップをウィザード化し、「準備できた」「モデルが未配置」「この端末では軽量モードのみ」を明示する。
- ブラウザ版は PWA としてインストール可能にし、同一 LAN 内のタブレットや別 PC からも制作画面へ到達できるようにする。

**実装の方向**

- 既存の `scripts/run_api_dev.sh` と Vite 起動を、`scripts/start_studio.*` に集約する。
- `/health` と `/models` の既存情報を使い、起動画面に「Studio の準備状況」を表示する。
- 起動後に重いモデルを即ロードせず、選択したメディアだけを準備する。初回ロードには「初回のみ時間がかかります」と表示する。

**成功条件**: ふだんの利用は Dock / ショートカットから 1 操作で画面が開き、失敗時は次の行動が表示される。

### 2. 最初の画面を「かんたん作成」に変える

**画面構成**

```text
┌─────────────────────────────────────────────────────────┐
│ 今日つくるもの  [画像] [動画] [音楽]    準備完了 / 軽量モード │
├─────────────────────────────────────────────────────────┤
│ 何を作りたいですか？                                      │
│ [SNS投稿] [キャラクター] [商品イメージ] [BGM] [自由入力]   │
│                                                         │
│ 1. 主役・内容      2. 雰囲気      3. 画角・長さ            │
│ [入力欄]           [選択肢]       [選択肢]                 │
│                                                         │
│ 作られる内容の要約: 「夕暮れの…、縦長、やわらかい光」       │
│                                      [生成する]            │
├──────────────────────────┬──────────────────────────────┤
│ 今回の生成・待ち時間・中止 │ 最近の結果 / 比較 / 採用       │
└──────────────────────────┴──────────────────────────────┘
```

- 初期表示はプロジェクトの作成やテーマ切替ではなく、メディア選択と「何を作るか」にする。
- `PromptForm` は目的別テンプレートを選ぶと、必要な 3〜5 項目だけを表示する。
- 現在の `Quick Controls` は、利用者の言葉に合わせて「サイズ」「雰囲気」「長さ」などに言い換える。
- モデルは「おすすめ（この目的に向く）」を既定で選び、未配置モデルは通常の選択肢ではなく「使えるようにする」にまとめる。
- `Project` は任意の「保存先」とし、未選択でも生成を妨げない。初回は直近プロジェクトを提案する。
- 現在の高度な設定、LoRA、seed、パスは **詳細調整** の disclosure に閉じ込める。

**成功条件**: 初めての利用者が説明を読まず、メディア選択から生成まで到達できる。

### 3. 「思い通り」を言語化しやすくする

単純な自由記述プロンプトだけでは、制作意図の抜け漏れと修正の困難さが残ります。生成前と生成後の両方で補助します。

**生成前: 意図の組み立て**

- 目的別に、入力を「主役」「動作 / 構図」「スタイル」「光 / 色」「避けたい要素」に分ける。
- 入力内容から実際に送信するプロンプトの自然文プレビューを表示し、編集可能にする。
- 画像にはアスペクト比、動画には長さ・カメラ、音楽にはムード・BPMを目的に応じた選択肢として出す。
- 固定のサンプルプリセットを、利用シーン別のテンプレート（例: EC 商品、SNS縦投稿、YouTube サムネイル、作業用 BGM）へ増やす。
- 生成前に「このモデルで得意なこと / 苦手なこと」「おおよその待ち時間・出力形式」を短く表示する。

**生成後: 次の一手を選べるレビュー**

- 結果の直下に大きく **採用**、**少し直す**、**作り直す** を置く。
- 「少し直す」を選ぶと、`構図`、`人物・物の形`、`雰囲気`、`色・光`、`文字を消す`、`長さ・テンポ` のような該当項目を選べる。
- 選択内容を既存の feedback の `issue_tags` に保存し、現在の reuse 機能に「何を変える variation か」を渡す。
- 直近 2〜4 件は同じ条件で横並び比較し、採用した出力の設定だけを残す。品質スコアは補助情報に留め、利用者の評価を主役にする。
- 採用後は「プロジェクトに保存」「書き出し」「この設定をテンプレートに保存」を近接配置する。

**成功条件**: 再生成の理由を選択でき、採用までに同じプロンプトを手入力で作り直す回数を減らせる。

### 4. 端末差を「利用不可」ではなく「できることの違い」に変える

ローカルファーストを保ったまま、ハードウェアごとに実行可能な範囲を明確にします。

- 起動時に CPU / RAM / GPU・Metal / CUDA、空き容量、モデルファイル、ブラウザ接続状態を診断する。
- 診断結果から、端末ごとに「標準」「軽量」「閲覧のみ」の利用モードを提案する。
- 軽量モードでは、低解像度・短尺・軽量モデルを明示したプリセットに切り替え、失敗する設定は選択できないようにする。
- 閲覧・選定・フィードバック・書き出しは、生成用マシンと別のブラウザ端末でも行えるようにする。生成マシンへの LAN 接続は明示的な設定とする。
- どうしても実行できないモデルは、理由、必要容量、導入手順、代替可能なモデルを一つの「準備センター」に集約する。

**成功条件**: 生成できないときも原因と代替アクションが表示され、利用者が設定やログを探し回らない。

## 優先順位と段階的な実施案

| 段階 | 実施内容 | 期待効果 | 主な対象 |
| --- | --- | --- | --- |
| P0: 日常利用の土台 | ワンクリック起動、起動診断、準備状態、エラー文言の改善 | 起動失敗と問い合わせを減らす | 起動スクリプト、`/health`、`/models`、App shell |
| P1: 迷わない生成 | かんたん作成、目的別テンプレート、日本語コピー、詳細調整への分離 | 初回生成までの時間を短縮 | `PromptForm`、プリセット、App レイアウト |
| P2: 結果を育てる | 採用 / 修正 UI、修正タグ、比較、テンプレート保存 | やり直し回数と意図ずれを減らす | Gallery、Feedback、Reuse、Project |
| P3: 環境の拡張 | 軽量モード、端末能力診断、LAN 閲覧、PWA / Launcher 配布 | 使える場所と端末を増やす | モデルサービス、設定、Web 配布 |

P0 と P1 を先に出すと、バックエンドの大規模変更を待たずに、もっとも大きい「面倒」「迷い」を解消できます。

## 計測して改善を続ける指標

- **起動到達率**: Launcher 起動後に Studio の準備完了画面まで到達した割合
- **初回生成までの時間**: 画面表示から最初の job を投入するまでの中央値
- **生成完了率**: job の成功率を、メディア・端末モード・モデル別に確認
- **意図一致率**: 利用者が「採用」した出力の割合。既存の semantic rating を補助指標にする
- **再試行効率**: 採用までの平均生成回数と、「少し直す」経由で採用した割合
- **継続利用**: 週あたりのアクティブ日数、1 日あたりの採用・書き出し件数

個人利用のローカルアプリなので、計測はまず端末内の集計に留め、外部送信を既定にしません。

## UI 実装時のガードレール

- 既存の Quiet Creative Workbench 方針を維持し、生成物以外の装飾は増やさない。
- 初期画面では主要アクションを 1 つに絞り、周辺の情報は段階的に開示する。
- 状態は色だけに頼らず、必ず「準備完了」「軽量モード」「モデル未配置」などのテキストを添える。
- 390px、768px、1280px、1440px で、かんたん作成・実行中・空・エラー・長文・多数履歴を確認する。
- 既存の高度な生成パラメータ、資産再利用、プロジェクト、フィードバックを削除せず、必要な場面に移動する。

## 最初のリリースで含めるべき範囲

1. `start_studio` による一括起動と、画面上の準備状態表示
2. 画像の「かんたん作成」フロー（用途、主役、雰囲気、比率、避けたい要素）
3. 結果の「採用 / 少し直す / 作り直す」と、修正理由を伴う variation
4. 既存の詳細 Composer、Gallery、Project 機能は「詳細調整」または「ライブラリ」として保持

この小さな切り出しで、毎日使う上での主な障壁を直接検証できます。動画・音楽、端末モード、PWA は、同じ情報設計を横展開する第 2 段階にします。
